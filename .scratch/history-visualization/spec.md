## Problem Statement

高中生学习历史时需要记忆大量事件、人物、制度及其背景和影响。用户认为现有学习过程缺少直观的时空组织，零散知识需要反复背诵，不容易把“何时、何地、发生什么、如何发展、影响哪些地方”联系起来。

项目希望以历史地图和时间线作为教材知识入口，让学生在浏览区域和年代时理解中国通史。是否提高记忆效果属于后续试用要验证的目标，不能仅凭网页可用便作出结论。

项目维护者还希望按业务能力组织模块，未来相似项目可以通过接口复用答题等能力，减少复制代码和与历史地图逻辑的相互依赖。这个长期目标不扩大本次首版的功能范围。

## Solution

提供一个先在本机验收的网页学习工具。进入页面后，视觉中心是可旋转的悬浮地球，顶部为时间线。用户选择时间段，进入中国及对应历史区域，在省级尺度以内浏览知识气泡和列表，点击后在侧边阅读发展流程、知识要点、背景与影响，并可展开教材原文及出处。

空间和时间联动：全球视图按百年，国家／区域按十年，省级尺度按一年。进入下一级保留起始年份并缩短区间，返回上一级恢复此前区间。地图显示区间起点的历史版图、区划与地名；气泡和发展主题反映整个区间，两种时间依据均需明确标示。

地图支持“政权／疆域”和“发展主题”两种着色模式，配套图例。气泡在相关区域附近定位即可，远处聚合显示数量，放大后展开；当前范围的全部知识仍可从侧边列表访问并按主题筛选。制度、思想以有依据的起源入口组织，后续传播与改革关联各自事件，多地点人物关系可以用连线展示。

内容以用户提供的高中历史教材为主，覆盖其中中国通史相关知识；允许以有出处的历史地图和地名资料补充。无法确定的事实和近似空间信息需要明确区分，不把资料不足呈现为没有事件。

首版聚焦浏览与学习。答题、徽章、学习记录、情景动画和手机端留待后续；不因规划模块化便提前实现这些能力。

## User Stories

以下为首版用户故事，按可观察行为和维护需要组织。资料交付、清单与审阅记录不意味着需要新增后台管理页面或上传功能。

1. 作为高中生，我希望打开网页时看到中心地球和顶部时间线，以便理解从空间和时间进入知识的方式。
2. 作为高中生，我希望旋转地球并选择区域，以便从感兴趣的位置开始学习。
3. 作为高中生，我希望在全球视图按百年选择时间段，以便了解较长时期的知识分布。
4. 作为高中生，我希望进入中国等区域后按十年浏览，以便进一步区分事件发生的阶段。
5. 作为高中生，我希望在省级尺度按一年浏览，以便查看更具体的年度事件。
6. 作为高中生，我希望进入下一级时保留原区间起始年份，以便空间放大时不丢失时间线索。
7. 作为高中生，我希望返回上一级时恢复此前时间段，以便继续原有的浏览过程。
8. 作为高中生，我希望地图在省级尺度内呈现可读的信息，以便集中学习而无需寻找精确街道坐标。
9. 作为高中生，我希望看到所选时间段起点的历史版图，以便理解该阶段的初始空间状态。
10. 作为高中生，我希望地图采用对应年代的行政区划与名称，以便理解当时的地域划分。
11. 作为高中生，我希望清楚看到版图参考时点与知识筛选区间，以便不把区间后期事件误认成起点时已经发生。
12. 作为高中生，我希望按政权／疆域着色查看地图，以便区分同时呈现的政权空间范围。
13. 作为高中生，我希望切换到战争、农耕、文化或科技等发展主题，以便关注一个方面的历史变化。
14. 作为高中生，我希望每种着色模式都有图例并保留疆域轮廓，以便理解颜色和区域的含义。
15. 作为高中生，我希望知识气泡出现在相关区域附近，以便把知识与大致地理位置联系起来。
16. 作为高中生，我希望远处密集气泡合并显示数量，以便看到知识分布而不被标签遮挡。
17. 作为高中生，我希望放大后看到聚合气泡中的具体知识，以便从概览进入细节。
18. 作为高中生，我希望侧边列表保留当前范围内的全部知识，以便地图气泡重叠时仍能找到条目。
19. 作为高中生，我希望地图与列表使用一致的主题筛选结果，以便两处显示互相对应。
20. 作为高中生，我希望单点事件按照发生时间出现在对应区间，以便正确建立时间顺序。
21. 作为高中生，我希望持续过程在与所选区间相交时仍可见并标出起止时间，以便理解它跨越多年的影响。
22. 作为高中生，我希望思想与制度有可靠的起源时间、人物或地点入口，以便理解它们的形成背景。
23. 作为高中生，我希望后续传播、改革等通过关联事件呈现，以便追踪发展而不把起源气泡误认为持续发生。
24. 作为高中生，我希望相关人物和地点能够通过有依据的连线关联，以便理解多地参与及影响范围。
25. 作为高中生，我希望点击气泡后侧边展开详情且地图仍然可见，以便在阅读时保留时空参照。
26. 作为高中生，我希望详情分块说明发展流程、知识要点、背景与影响，以便按结构理解事件。
27. 作为高中生，我希望可以展开教材原文及章节／页码，以便核对整理内容的依据。
28. 作为高中生，我希望从详情返回知识列表并继续浏览，以便比较同一时期的不同条目。
29. 作为高中生，我希望不确定事实和示意空间范围被明确标示，以便知道信息的可靠程度。
30. 作为高中生，我希望能区分教材原文、整理内容和补充资料，以便理解不同表述的来源。
31. 作为高中生，我希望文字可读、气泡可点、必要操作不被面板遮挡，以便完成连续学习。
32. 作为高中生，我希望教材中的中国通史知识得到系统覆盖，以便不只看到少量热门事件。
33. 作为高中生，我希望重复出现的知识能整合并关联多个出处，以便减少重复浏览且不丢失教材依据。
34. 作为内容维护者，我希望以提供的整套教材建立知识清单，以便明确首版实际覆盖范围。
35. 作为内容维护者，我希望补充地图和地名资料时记录来源与年代，以便后续核对历史空间信息。
36. 作为内容审阅者，我希望知识清单能对应展示入口、详情和出处，以便逐项确认内容是否遗漏。
37. 作为内容审阅者，我希望缺项和无法确认的内容单独列出，以便区分已完成内容与仍需补充的工作。
38. 作为项目负责人，我希望在本机运行并验收完整浏览路径，以便先确认产品与内容可用再考虑对外提供。
39. 作为项目负责人，我希望功能检查、内容核验和未解决问题分开报告，以便准确判断交付状态。
40. 作为维护者，我希望功能变化能够关联到会话、修改位置和验证结果，以便出现问题时追溯变更。
41. 作为维护者，我希望实际问题保存现象、证据、原因、处理及验证记录，以便再次遇到时复用排查经验。
42. 作为开发者，我希望业务能力通过明确接口组合，以便后续加入或提取模块时减少对其他能力的影响。

## Implementation Decisions

### 已确认的产品与工作规则

1. **首版交付**：网页端、本机验收、中国通史内容。地球入口不意味着首版必须补齐全球其他地区历史。
2. **三档时间粒度**：百年、十年、一年；不提供五年切换。向下进入区域保留起点并缩短区间，返回恢复原区间。
3. **导航状态**：当前页面内可以保留区域、区间与返回上下文，刷新后不恢复学习记录；不将短期导航状态等同于已读或掌握程度。
4. **历史空间**：版图、区划与名称对应区间起点；省级为观察尺度，实际历史层级以资料为准；同一年内的具体日期精度需要依据资料标注。
5. **着色语义**：政权／疆域着色与发展主题着色可切换，疆域轮廓保留，图例解释当前模式。主题覆盖所选区间，版图取起点，分别标明时间依据。
6. **知识筛选**：单点按发生时间，明确持续过程按与区间相交显示。起源条目与后续传播、改革分别表达，后续关系须有内容依据。
7. **聚合和访问**：气泡允许相关区域附近的近似位置。远处聚合、放大展开，侧边列表提供当前范围的完整访问途径；同一筛选条件下数量与条目应一致。
8. **阅读路径**：侧边详情默认展示发展流程、要点、背景与影响，可展开教材原文及章节／页码；地图、选中条目和有依据的相关地点连线保持关联，可返回列表。
9. **内容处理**：原教材与整理结果可追溯；重复知识整合多个出处；无法确认的事实标待补充，近似空间表达标示意，不编造起源、日期和边界。
10. **覆盖与数据来源**：建立教材中国通史知识清单，逐项关联展示内容。允许有出处的历史地图及地名资料补充，不把占位或演示样例计入正式覆盖。
11. **工作记录**：有实质工作或决定时更新会话日志，结束前补齐修改位置、证据和未完成项；遇到实际问题先检索已有记录，按问题维护假设、原因、处理和验证状态。
12. **当前实施事实（2026-09-20）**：已采用 React + TypeScript + Three.js + Vite，以历史知识、地图探索、学习阅读和项目组合实现；有 Playwright 测试。详情见技术方案和阶段验收报告，真实教材与历史地图数据仍未到位。

### 模块化目标与候选划分

用户已提出按功能形成模块、通过接口组合并支持后续跨项目复用的目标。此前分析给出了候选方案，尚未确认具体拆分、接口形态、代码包发布或独立服务部署；本规格保留这种区别。

| 候选模块 | 职责 | 候选公开交互 |
| --- | --- | --- |
| 历史知识 | 知识与出处、时间和区域归属、主题筛选、详情查询 | 接收浏览条件，返回一致的知识结果和详情 |
| 地图探索 | 地球、历史版图、区域选择、缩放、时间导航和气泡呈现 | 接收展示数据，报告浏览条件与知识选中行为 |
| 学习阅读 | 当前知识列表、详情、原文和出处阅读 | 接收阅读数据，报告条目选择与返回行为 |
| 项目组合 | 协调上述能力及页面状态 | 将地图选择转换成查询，并把一致结果传给地图和列表 |

候选方向是先按模块组织、同一网页应用内运行；公开接口隐藏内部实现，避免其他模块直接读取内部状态。模块可以包含多个内部文件，不以“一模块一文件”作为约束。调用约定需要涵盖输入、输出、错误和状态要求，而不仅是函数名。

未来答题模块应可与历史区域、时间筛选和徽章规则分开：历史项目确定题集，答题能力完成作答与结果处理，项目消费结果。具体采用独立代码包、复用界面还是 HTTP 接口仍未决定，首版不实现相关代码。

### 尚未锁定的实现细节

- 技术栈、地图工具、存储及运行命令已在根目录技术方案.md 和 README.md 落实；全量内容性能预算仍待实际资料。
- 教材版本、起止年代、地图数据可用性，以及无法精确到年份或具体日期的内容表达细节。
- 时间区间端点、跨公元纪年、资料覆盖末端等在数据模型中的统一表示方式；实现时须明确且可验证，不能使边界事件重复或遗漏。
- 浏览过程中历史行政区域发生变化、所选历史区域在新时点不存在时的具体交互。处理方式应与“按当时区划显示”一致，不静默换成现代行政区。
- 初始年代、具体配色和主题字典、空数据及数据加载失败状态的细化。这些不是已经确认的新功能。

本节不指定源代码路径或未经确定的接口签名，不把候选方案写成已完成的技术决定。

## Testing Decisions

### 已确认的验收原则

验证用户可观察的行为及返回结果，不依赖内部文件位置、私有函数名称或某种技术库的调用次数。功能检查、结构完整性、历史内容核验分别报告；解析或数量检查不能替代内容正确性审阅。

首版按完整路径、时空对应、教材覆盖、内容出处和本机可用性验收；样例或占位不算全量完成。测试报告说明覆盖范围、实际结果及未解决问题，不把软件验收等同于学习效果验证。

### 已确认的主要测试入口：浏览器公开学习路径

**状态：用户于 2026-09-18 明确确认。**

以网页对用户暴露的完整学习入口作为一个主要测试接缝：旋转地球 → 选择时间 → 进入区域 → 查看气泡／列表 → 阅读详情 → 返回。通过界面操作观察所选时间、区域、版图说明、列表、详情与出处，验证候选地图探索、历史知识、学习阅读及项目组合能力是否协同正确。

教材覆盖和历史内容核验是独立的内容审查工作，不需要为其额外暴露应用内部测试接口。若实际性能或数据体量要求增加模块级检查，再在已形成的公开模块接口处补充，不预设每个文件都要有单独测试接缝。

现有测试（2026-09-20 更新）：tests/ 中的 Playwright 测试覆盖演示浏览路径；验证结论见阶段验收报告。历史内容核验仍独立待资料。
